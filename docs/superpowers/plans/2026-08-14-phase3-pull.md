# Pull Merge and Rebase Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Pull the current branch's upstream safely, fast-forwarding when possible and allowing an explicit merge or rebase when histories diverge.

**Architecture:** Pull fetches through the transfer service, then git-core compares HEAD and its fetched tracking ref. The frontend routes divergence to the existing Phase 2 merge and RebasePlanner flows.

**Tech Stack:** Rust 2021, git2 0.21, Tauri 2, React 18, TypeScript, Vitest, WebdriverIO.

**Spec:** docs/superpowers/specs/2026-08-14-phase3-remote-workflows-design.md

## Global Constraints

- Pull requires a clean index and worktree; Fetch remains available when dirty.
- Pull always fetches before comparing histories.
- Reuse existing merge conflict resolution and interactive rebase UI; create no parallel resolver.
- Merge, rebase, and transfer controls are mutually exclusive.
- No force update or automatic merge/rebase choice.

- [ ] **Step 3: Implement explicit outcomes**

~~~rust
pub enum PullOutcome {
    UpToDate,
    FastForwarded { upstream_ref: String },
    Diverged { upstream_ref: String },
}

pub fn pull_after_fetch(
    repo: &Repository, remote_name: &str, remote_branch: &str,
) -> Result<PullOutcome, RemoteError>;
~~~

Inspect status before any checkout. Resolve refs/remotes/{remote}/{branch}; use graph_descendant_of to classify equality, local-behind, and divergence. For a fast-forward, move the current local branch and force-checkout with CheckoutBuilder only after the clean-tree check. Do not call merge or rebase from git-core for the divergent case.
