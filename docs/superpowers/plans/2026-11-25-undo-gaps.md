# Undo gaps: plan

Design: `docs/superpowers/specs/2026-11-25-undo-gaps-design.md`. Each task: a test-only commit
(red run quoted; type scaffolding only where the tests need it to compile, said so), then the
implementation commit. The git CLI checks results where it is the reference
(`test_support::git`, failing without git).

## Task 1: Create and switch is a full entry (#1154)

- `policy_tests.rs` (`Test change:` commit): `CreateBranch { checkout: true }` row expects
  `undo(Full, Create branch topic)`.
- `worker/tests/undo.rs`: `master` has `a.txt` = "a"; `other` changes it and adds
  `only-other.txt`. `create_branch("feature", "other", true)`, `undo()` → `Done`; `git status
  --porcelain` is empty, `a.txt` is "a\n", `only-other.txt` is gone.

Code: `policy::of` reads `checkout`.

## Task 2: Undo/Redo stream big files (#1089)

- `crates/git-core/tests/undo_restore_memory.rs` (own binary, Linux, `VmHWM`): `data.bin`
  committed small, replaced by a 64 MiB file, `FullUncapped` before, `discard_file`, after.
  `restore(after → before)` and then `restore(before → after)` each raise the peak resident
  size by less than 16 MiB; the file is back each time (`git hash-object`).

Code: streaming compare (`blob_matches_file`) in `verify`, `already_restored`, `holds_blob`;
`Content::Stream` for `write_worktree_file`.

## Task 3: discards store whole only their paths (#1104)

- `crates/git-core/tests/undo_whole_paths.rs`: with `capture_limited_except` (untracked limit
  3, file limit 10 bytes): 5 untracked files and a big tracked file not named are left out
  (listed / skipped), the named ones (a file, a folder prefix, a different case) are stored;
  a discard of a named file between two such snapshots undoes and redoes.
- `policy_tests.rs`: a new test pins `UndoPlan::whole` per discard command (Apply patch:
  the patch's paths; Reset hard: `None`).
- `patch::touched_paths` for a two-file diff and a mail with a rename.

Code: `capture_keeping`, `Limits::whole`, `UndoPlan::whole`, `patch::touched_paths`.

## Task 4: sparse checkouts and intent-to-add; format version 3 (#1174)

- `crates/git-core/tests/undo_sparse.rs`: in a `git sparse-checkout set app` repository, stage
  `app/main.rs`, Undo → `Ok`, `git status --short` empty, `git ls-files -v` keeps the `S`
  marks; Redo too. A `--skip-worktree` file with local edits: Undo of a stage keeps the mark and
  the edits. `git add -N new.txt`, then stage `a.txt` and undo: `git status --short` shows
  ` A new.txt` again (intent-to-add kept), Redo the same.
- `undo_store` unit test: a snapshot with intent-to-add paths saves as version 3 and reloads.

Code: `RepoSnapshot::intent_to_add`, `restore` without the refusal, marks restored,
`FORMAT_VERSION = 3`.

## Task 5: branch settings (#1151)

- `crates/git-core/tests/undo_branch_config.rs` (git CLI `branch -vv`, `config --get-regexp`):
  rename with upstream → undo: old name has the upstream, no section under the new name; redo:
  the reverse. Current branch renamed → undo: `git status -sb` shows the upstream. Delete →
  undo: upstream back; redo: section gone. Undo of a rename after the new name's upstream
  changed → `RepositoryChanged`, nothing written.
- `worker/tests/undo.rs`: checkout of a remote branch (create + set upstream), undo, redo:
  upstream present.
- `undo_store` unit test: `branchConfig` saves and reloads.

Code: `RepoSnapshot::branch_config`, capture, `changed_refs_only` trims, `restore` checks and
writes.

## Task 6: work-tree entries (#1147)

- `worker/tests/undo.rs`, the issue's two cases: discard during a conflicted merge →
  `get_undo_state().undo` is the discard; `undo()` → `Done` and `b.txt` back; redo; after
  `abort_merge`, the entry still undoes. Discard after a conflicted stash pop (no operation) →
  recorded, undo brings the file back. Reset hard after a conflicted stash pop → refused with
  the conflicts message, nothing changed. Apply-and-stage patch during a paused merge → refused.
- `crates/git-core/tests/undo.rs`: `capture_worktree` with a conflicted index has no index
  tree; `restore_worktree` restores a file while a merge is in progress; it refuses when the
  file changed since.

Code: `capture_worktree`, `restore_worktree`, `RepoSnapshot::index_tree: Option`, recorder
`begin` (decides entry kind or refusal), `finish`, `step`; worker loop refuses.
